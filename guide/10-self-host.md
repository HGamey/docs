# 自行部署中心节点与执行机

本文面向需要自建平台的团队，只说明阅读顺序与模块组合，命令与验收见各章。

## 角色

- **中心节点**：运行任务队列、研究库、网页和 HTTP API，人员与 agent 只与中心交互。中心所在电脑也可以直接连接手机。
- **执行机**：连接手机的其他电脑，主动连接中心并接受统一调度，无需入站端口。

两者可分别部署：先部署中心，执行机随时按需加入，中心无需改动。

## 部署中心节点

按以下顺序阅读：

1. [01 设备层](01-device-layer.md)：安装 phonefarm 并设置设备锁目录，中心不连接手机时同样需要。
2. [02 节点服务与网页](02-node-service.md)：生成管理 token 和网页口令，注册系统服务，通过 `deploy.py` 发布。
3. [05 公网入口](05-public-access.md)：执行机或 agent 不在同一内网时配置；仅在内网使用时跳过。
4. [04 Agent 接入](04-agent.md)：管理员使用 `pf-node`，为 agent 签发邀请码。

实验代码默认从 HGamey/experiments 按提交号获取；如使用自有仓库，在启动配置中添加 `--experiments-url <仓库地址>`（见 [07](07-demo-setup.md) 的准备一节）。

## 部署执行机

1. [01 设备层](01-device-layer.md)：在执行机上安装依赖并连接手机。
2. [03 执行节点](03-execution-node.md)：在中心生成机器邀请码，执行机通过 `deploy.py join` 加入。

## 可选与参考

- [06 自研超分与插帧](06-selfsr.md)：需要在 root 手机上运行超分、插帧实验时阅读。
- [07 Demo 环境搭建](07-demo-setup.md)：两台电脑加一台手机的完整示例，含内网无法访问外网时的准备工作，可作为整体演练。

## 最小可行组合

| 规模 | 中心 | 执行机 |
|---|---|---|
| 一台电脑，内网使用 | 01 + 02 + 04，手机直连中心 | 无 |
| 多台电脑，同一内网 | 01 + 02 + 04，`--host` 改为内网地址 | 每台 01 + 03 |
| 执行机或 agent 分布在不同网络 | 01 + 02 + 04 + 05 | 每台 01 + 03 |

每章的验收全部通过后再进入下一章。部署完成后，用 `deploy.py --status` 记录中心部署的提交号，后续升级与回滚以此为准。

## 交给 agent 时

部署中心节点：

```text
阅读 https://github.com/HGamey/docs/blob/main/guide/10-self-host.md ，按"部署中心节点"一节的顺序部署中心节点，安装根目录为 ~/node。
网络：<仅内网 / 需公网访问>。每章验收通过后再进行下一章，完成后汇报 deploy.py --status 的输出和网页地址。
token 与口令只保存在本机文件中，不得写入对话、日志或仓库。
```

部署执行机（先由管理员在中心执行 `pf-node nodes invite` 获取机器邀请码）：

```text
阅读 https://github.com/HGamey/docs/blob/main/guide/10-self-host.md ，按"部署执行机"一节将本机加入中心。
中心地址：<中心地址>；机器邀请码：<机器邀请码>；节点名：<节点名>。
完成后汇报 deploy.py --status 的输出。
```

执行机加入后，管理员在中心执行 `pf-node nodes show <节点名> --devices`，确认能看到该机连接的手机。
