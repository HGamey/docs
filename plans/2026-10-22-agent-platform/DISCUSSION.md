# 第一批讨论记录

日期：2026-10-22。前两轮问题已经回答；这些决定无需再次向用户索取确认。

| 议题 | 用户决定 | 对实现的约束 |
|---|---|---|
| 项目目的 | Agent远程真机、可复现与可审核、系统性优化指定游戏、探索多方向 | 远程任务/证据是主干，不把超分当唯一路线 |
| 人的作用 | 技术指导；协助采集/解除阻断；图像/视频主观评价 | 人是异步参与者，提供有上下文的协助入口 |
| 等人时如何运行 | 某方向可阻断，仍有方向就继续探索、排序和实验 | 阻断表达为依赖关系，不能做全局“等待用户”状态 |
| 谁做方向决策 | 外部Agent | 平台管理资源、状态与约束，不强制内置优化调度Agent |
| harness形式 | prompt+系统功能即可，不必内置Agent | 同一套能力可以被不同Agent工具和网页使用 |
| 远程控制档位 | Agent API/CLI + 人工看屏、随时接管 | 同一设备ownership下交接，测量/观察互斥 |
| 首批主线 | 多机管理→游戏/任务分发→队列调度→结果汇总 | 先形成完整工作流，不继续堆一次性实验helper |
| 交付优先级 | 网页与CLI/API同等优先 | 每批验收都有两侧能力，不能CLI做完再考虑网页 |
| 共享状态 | 游戏目标、方向、实验、人类反馈独立于Agent工具持久化 | 聊天历史留原工具；状态可交接、续做、跨Agent协作 |
| Git流程 | 直接commit/push，不新开PR；用户明确授权管理员修改GitHub规则 | 取消强制PR，保留必需检查及禁止强推/删除；先在verify分支检查同一提交再直推main |
| 当前实验数据 | 先留本机，准备交接 | 不为规划上传原始数据或再争论后台主机 |
| 优化权衡（此前已明确） | 可接受PSNR下降换性能；模块ms收益也有意义 | 目标可配置，多指标分别报告，不强制胜双线性 |
| 维护者手册审计 | 优先核对思想与产品目的，软件问题可改；持续记录对话和思想 | 区分用户决定、作者报告、源码证据与判断；共同准则见PRODUCT-CHARTER |
| 持续开发目标 | 按讨论与计划优化、开发所有可用项目，完成开发内容 | 进入分批实现；不把审计文档当开发完成，不把所有项目一律重写 |
| 提交节奏 | 稳步开发、频繁commit并push；有并发内容pull --rebase | 小批独立验证，重放后核查冲突和必要回归，不force push |
| 前端参考 | Taste Skill、Archify；注意间距、配色、交互与按钮反馈 | 设计与行为共同验收，不能只接通接口就宣称网页可用 |
| 团队执行 | subagent可负责明确的具体开发任务；主Agent重点放在系统，前端尽量委派 | 划分文件所有权；主Agent聚焦状态/所有权/协议/整合，真机仍保持唯一owner |
| 实现复杂度 | 精简测试，不堆无意义hash，减少防御编程，多思考结构和原理 | 关键边界集中实现，测试回答真实行为问题；不以测试数或校验字段数量衡量可靠性 |
| 执行连续性 | 经常阅读plan/todo，逐条完成，想到要做什么先加入todo，不频繁切换手头工作 | 每批只推进明确验收范围，发现邻接问题先记录；仅本批必需的兼容修复一起完成 |
| 旧PR近期合并 | 担心历史变更影响当前版本，安排subagent研究 | 只读核查近期合并记录、最终代码和具体回归；不因PR年代久就自动回滚 |

## 本轮从使用经验得出的判断

1. “用phonefarm启动了”与“平台能发现、分享、续做这次研究”之间还有很大缺口，不能把任务执行包装当完整接入。
2. 远程控制能力已有基础，但输入、看屏、lease、测量没有形成统一会话。需要把执行与反馈闭合，而不只是增加更多adb命令。
3. 本机研究中反复出现的构建、资源准备、采样、恢复、原件传输和分析包装，应提炼为通用能力；新实验不应再复制一大套task helper。
4. 现有证据纪律值得保留，但要分层、自动复用资格和清楚表达未知，不能让每次探索都背上最终确认的全部成本。
5. “外部Agent不会等待人”需要持久异步对象与可继续路线，也需要参考prompt/客户端行为约定；仅加一个网页聊天框不能保证实现。

## 尚未定案，但不阻断首批设计的技术选择

- 轻量状态存储用SQLite还是已有JSON事件日志；先按恢复、并发和迁移测试决定，不先引入分布式基础设施。
- 看屏先复用截图通道，低延迟流使用什么方案；依据实际节点/手机能力和观测开销验证，不为所有平台承诺同档能力。
- harness-ops与phonefarm是否最终合仓；先统一合同、安装和版本，历史搬迁留到收益明确后。
- 具体中心服务器、域名、索引副本和大文件存储位置；用户已选择暂缓。本机实现与远程节点接口不能被这个选择卡住。
- 外部Agent的唤醒/通知适配；先提供事件游标/状态查询，按具体客户端补适配。平台不凭空获得唤醒停止中的Agent进程的能力。
- 第一轮真实多机验收用哪些在线设备；本轮没有探测手机，待实施进入实机验收时按已有授权与lease核实。

这些选择由实现阶段给出具体候选、成本和可审阅结果；只有出现新的产品边界冲突时才集中留言讨论。当前无需重复讨论上述已确认目的。
