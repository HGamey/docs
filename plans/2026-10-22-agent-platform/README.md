# HGamey：面向外部 Agent 的远程真机优化平台

2026-10-25。状态：**主干源码与隔离宿主验收已形成阶段版本，准备部署验证；完整真机流程尚未验收。交接后暂停自动开发，整体不标完成。** 先读[阶段总结与部署顺序](STAGE-20261025.md)，再按todo的DEPLOY清单推进。

让外部 Agent 使用远程真机，系统性优化指定游戏/系统，探索多个方向，完成可复现实验并留下可审核结果。平台提供设备、分发、任务、证据和异步协作能力。harness 可以由 prompt 加这些系统功能构成，不要求另造一个内置 Agent。

## 已确认的产品决定

1. 第一批主线：**管理多机 → 分发游戏和任务 → 排队调度 → 汇总结果**。
2. **网页与 CLI/API 同等优先**。Agent 能调用的核心状态和操作，人也能在网页查看或执行；看屏和人工接管是正式能力。
3. 人可以异步给技术建议、帮助收集数据/处理阻断、评价图片或视频的质量与偏好。
4. 协助请求持久化，只阻断依赖它的方向。外部 Agent 决定方向优先级，只要有可行工作，就继续探索、验证和看结果。
5. 共享研究状态包括游戏目标、方向列表、实验、产物和人类反馈，独立于 Agent 工具。聊天历史仍在原工具中。
6. 用户允许性能与画质权衡；实验目标和质量预算可配置。模块 ms、显示 FPS、功耗、每帧能耗及主观质量分别报告。
7. 开发直接 commit、push，不新开 PR。小批提交、明确验证、保留同事改动，避免长时间无人合并的分叉。

## 第一批成功的样子

外部 Agent 和网页看到同一组节点/手机、游戏版本和任务。Agent 分发已有游戏清单并提交多条工作；一条因设备或人类协助阻断时，另一条继续。关闭客户端或重启节点后可找回同一任务；人可看屏、接管并归还控制。结果包含失败项，能按目标、方向、游戏、设备找到原始证据，用只读权限查看与下载。全部过程不要求使用某种内置 Agent 或特定 goal 目录。

两台手机不在线时先用故障注入和虚拟节点验证协议，实际设备验收单独记录，不能把模拟通过写成真机通过。

共享读取合同见[节点与设备状态读取](FLEET-API.md)与[跨节点目录](FLEET-DIRECTORY.md)。网页可显式选择已登记节点并查看缓存快照；目录可达不代表设备在线或可操作。跨节点调度、部署与真机验收范围以 [todo](todo.md) 和 [逐批记录](BATCHES.md) 为准。
