# 产品讨论：Agent 身份与任务可见性层

2026-10-27。用户提出：平台应该是分布式（核心在 mbp1，别的机器接入提供手机，任何能访问核心的 agent 都能控制手机），但当前缺少 **agent 标识层**——多个不同地点的 agent 同时使用时，互相抢占手机、正在做什么没有清晰规划。

## 当前事实（代码层面）

| 概念 | 现状 | 局限 |
|---|---|---|
| node | 持久 ID、目录注册、跨节点检索 | 只有节点身份，没有"谁在操作" |
| device | 人工登记、lease 唯一 owner | 全局 lease，不区分是哪个 agent 在用 |
| job | 幂等 request_id、队列、取消/恢复 | 任务没有"发起者"字段 |
| research | 方向/协助/反馈、事件流 | 方向没有"属于哪个 agent" |
| 人工介入 | dash steer 密码、任务级操作 | 介入是"有密码的人"，不是"针对某个任务的介入" |

## 用户提出的问题

1. **agent 标识**：不同地点的 agent 正在使用平台，互相之间不知道对方在做什么。
2. **任务归属**：agent 不知道"我正在做什么任务"的清晰标识；其他人不知道"这个任务是谁的"。
3. **手机分配**：lease 是全局唯一 owner，但**不是按 agent 划分的**——谁抢到 lease 谁用，没有"分配给某个 agent"的语义。
4. **人工介入范围**：现在介入是全局的（有 steer 密码就能操作），应该是**针对一个任务**的介入。

## 需要讨论的决定

### A. Agent 身份模型

- **A1 轻量**：job/research/direction 加 `actor_id` 字段（声明式，不验证），Agent 提交时自报身份。
- **A2 中量**：平台注册 agent 身份（类似 device registry），有 token 或标签，agent 列表可见。
- **A3 重量**：完整认证（agent 身份 + 权限范围），区分"哪个 agent 能操作哪些设备"。

### B. 设备分配语义

- **B1 当前**：全局 lease，先到先占。
- **B2 改进**：设备绑定 agent——`device_binding` 加 `owner_agent` 字段，或 lease 按 (device, agent) 划分。
- **B3 显式分配**：管理员/用户显式把设备"分配给"某个 agent 一段时间，其他 agent 可见但不可抢占。

### C. 人工介入范围

- **C1 当前**：steer 密码全局，任何有密码的人能操作任何任务。
- **C2 改进**：介入按任务/方向粒度——"我介入这个任务"而不是"我接管整个节点"。
- **C3 更细**：介入有"观察/建议/接管"三档，接管才需要更高权限。

### D. 网页交互梳理

- 当前 dash 页面（任务/节点/游戏/研究/维护）是节点级视图，没有"当前 agent 视角"。
- 需要加"我是谁"、"我在做什么"、"其他 agent 在做什么"、"设备分配给谁"的可见性。

## 我的建议（供讨论，不实现）

1. **先做 A1**（actor_id 声明）：最小改动，立即改善可见性——每个 job/research 记录"谁发起的"，网页显示。
2. **B2 按 agent 划分 lease**：device_binding 加 owner_agent，lease 按 (device, agent) 互斥——不同 agent 用不同设备并行，同 agent 同设备串行。
3. **C2 任务级介入**：dash 的"接管"按钮从全局改为任务级——"接管这个任务"而不是"接管节点"。
4. **D 页面加 agent 视图**：任务页加"发起者"列，研究页加"我的方向"过滤。

## 用户决策（2026-10-27）

| 问题 | 选择 |
|---|---|
| Agent 身份模型 | **A2 注册身份** |
| 设备分配语义 | **B1 当前（全局抢占）+ agent 短时间持有空闲设备保护（30min）** |
| 人工介入范围 | **C1 全局 / C2 任务级（并存）** |
| 网页交互 | **加 agent 级视图 + Task 视图 + Task 当前由什么 agent 负责** |

**新增需求**：
- 网页+CLI 加 agent log——agent 定期上传目的/方向供用户和其他 agent 查阅。
- 网页+discuss 模块——每个任务有自己的 discuss 模块（人工和 agent 讨论，agent 有问题想问人，其他 agent 可参与）。

**整体目标**（用户原话）：
> 我们不希望重新发明一个 harness 框架，但是希望我们这里能够给 agent 提供一个明确的工作平台。agent 在这边干活的时候，他知道他在做什么，他了解自己的环境，我也知道他在做什么，有展示性，同时能及时介入。
