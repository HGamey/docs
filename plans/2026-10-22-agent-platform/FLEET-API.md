# 节点状态读取合同（2026-10-22）

目的：网页与 Agent 查询节点/设备状态时不创建作业，不要求管理 token；所有登记节点有结果，过期与未知不伪装为空闲。

## 单节点读取

- `GET /node`：现有宿主身份接口，不采手机。
- `GET /fleet?wait=0..5`：只读 token 可用，显式请求设备状态；允许等待当前采样最多5秒，随后返回现有快照/未知状态，后台采样有40秒上限。
- `GET /dash/api/fleet`：同一数据与采样器，用现有网页查看权限。`/dash/fleet` 展示本节点，不能写成跨节点控制台。
- `pf-node fleet [--wait N]` 与 `pf-fleet status` 读同一合同；旧节点404返回升级提示，禁止偷偷提交查询任务。

JSON字段：`schema_version=1,node_id,now,lock,devices,notes,sampled_at,age_s,stale,refreshing,error,deferred,policy`。
`devices=null` 表示尚未成功取得；`[]` 只表示一次成功采样确实没有设备。采样失败保留最近一次成功的数据和采样时间，error单独显示；旧数据不能被当作当前设备能力。
`lock.status=free|held|unknown`，附owner/since/heartbeat_age_s/stale/queue/recent/free_for_s/error。心跳旧不意味着锁空闲；目录存在而owner读不到、锁数据读取失败都不能报空闲。此处是旧全局devlock桥的可见状态，不能冒充强lease或逐设备调度。

## 单一采样所有者

节点服务持有一个 FleetState，旧dashboard和新API共用，不创建两套线程。仅显式设备状态/既有观察页面请求激活采样；node/jobs/静态资源不激活。空闲30秒、占用60秒、90秒无人请求停采，快照超过90秒标旧；旧桥释放后30秒、锁状态未知或心跳超期时暂缓。失败不清空最近成功快照。每次采样重新读锁，不继承调用Agent的DEVLOCK_LABEL。

新设备页/API只读元数据，不主动截图。既有首页/维护页的截图仍遵守旧空闲和间隔规则；与实验测量的完整资源协调单列CTRL待办，不能把本批写成已解决。没有真机验证，不部署运行节点。

## 跨节点查询

客户端每个登记节点预置结果；并行查询共用总deadline，逾时结果仍保留且标错，迟到线程不改已返回结果。可达、锁状态、设备采样是否成功/过期分开呈现。自动选空闲节点要求新鲜成功快照、lock free且队列空；明确指定节点仍由服务端实际锁协议排队。读取快照不是资源预留，原子调度仍未实现。

## 本批必要验证

用模拟采样验证无人请求不采、API/网页共享、无job/无截图、未知/过期/失败保留；客户端验证完整超时列表与只读GET；浏览器验证数据空态、锁未知/占用、失败重试、隐藏暂停和三个宽度。复用现有协议测试，不新增镜像测试矩阵。真实节点与手机验收另记。
