# 可控、直观：平台开发计划

2026-11-06 启动。来源：Doom 超分完整 E2E 记下的平台问题，加上用户和领导对平台的意见（"不直观、弯弯绕绕、字一堆，agent 不可控"）。用户说已讨论清楚，全面开工。

平台已部署在华为蓝区。领导的三个展示场景是验收参照：

1. 可视化展示分布式：主节点在深圳公网，从节点在成都公网或蓝区，agent 来自公网和蓝区。
2. 独立中心节点一键切换成从节点，接入更大的手机池。
3. 给一段自然语言、伪代码或 Python 描述的算法，agent 实现媒体算法、修改渲染管线、分发到真机执行并采集结果；控制台上能看到平台从 agent 收到什么、发给手机什么、返回给 agent 什么。

规则：一项一个 PR，验收看得见（截图、命令输出、真机结果），先在 rhodes1 验证再上 mbp1；每人同时只做一项；不加防御性兜底。

## 可控

| 编号 | 做什么 | 验收 | 负责 |
|---|---|---|---|
| K1 | **子节点同等控制权，并且一眼能发现**。中心已能用 `--device <节点>/<设备>` 把作业派到子节点，但没人知道。网页的手机列表要列出所有节点的手机（节点名、在线与否、root、系统、能否装包或推文件），派任务和远程控制都能选任意节点的手机。人用的远程控制（/dash/control）对子节点的手机也要能装包、推文件、跑命令，不只是点按和截图 | 网页上能看到并操作 office-ubuntu 的红魔；从中心给它派作业、装包、截图都成功 | Codex-Sub（后端），Claude-Sub（网页） |
| K2 | **节点自动更新**。中心公布推荐版本；节点空闲（没有在跑的作业）时自己拉取、构建、切换，失败自动回滚；网页显示每个节点的版本和落后多少；节点主人可以暂停 | 一个落后的节点在空闲时自动升到推荐版本并报告新版本号；故意构建失败时回滚到原版本；有作业在跑时不升级 | Codex-Sub |
| K3 | **"成功"要有证据，失败要冒出来**。出图的作业自动生成缩略图拼图，挂在任务页；同一作业里截图完全相同时标出来；任务页顶部显示最近失败的作业；在产品里指派任务或用户留言标"紧急"时，负责的 agent 下次签到就能看到并被叫醒 | 拿本轮 Doom 采集的报错弹窗批次回放，任务页一眼能看出"不是游戏画面"；指派后 agent 的签到待办里出现这项 | Codex-Sub（后端），kimi-web（网页） |
| K4 | **每个任务的数据流向**。控制台上对任意任务列出：平台从 agent 收到什么（命令、代码提交、输入文件）、发给手机什么（装的包、推的文件、执行的命令）、返回给 agent 什么（输出、截图、日志） | 打开本轮 D 轨任务，三栏内容和作业记录一致 | Codex-Sub（后端），Claude-Sub（网页） |

## 直观

| 编号 | 做什么 | 验收 | 负责 |
|---|---|---|---|
| Z1 | **指挥中心：按下播放的那一刻进入跟随**。不是把播放和跟随绑定：自由移动时不跟随，按播放切进跟随，播放中拖动照样解除 | 交互脚本覆盖三种情况 | kimi-web |
| Z2 | **新增"结构"页**：主节点 → 从节点 → 手机 → agent 的分布式结构图，标出每个节点和 agent 所在的网络区域（深圳公网、成都公网、蓝区），可拖动，外行一眼能看懂 | 用真实节点数据（mbp1、office-ubuntu、kamico-mac）出图，1440 和 390 宽度截图 | Claude-Sub |
| Z3 | **任务页重构**。用户划分的叫"任务"，agent 自己拆的叫"作业"，作业默认收起；任务页顶部是结论和关键对比（比如 A–D 排序），能点进子任务；交付报告单独一页，默认显示最新版全文，历史版本折叠 | 原神超分任务和 Doom D 轨任务按新页面截图，交付页打开就是终版全文 | Claude-Sub |
| Z4 | **看得见 agent 干了什么**。任务的成果按文件列出并标类型（权重、引擎库、代码提交、图片、报告），代码提交链到 GitHub 并显示改了哪些文件，不再只显示作业号 | A 轨成果页上 base.npz 等权重一眼可见，Doom 放回的提交能点开看改动 | kimi-web |
| Z5 | **"打开游戏"验收页**。选某次研究的某个结果（比如 5 个模型里任选一个）和一台手机，平台用它打开游戏；也能一键打开原版。每项优化做成能单独开关的一项，平台先在固定回放上量出各项和组合的帧率、画质、功耗并排序，人只对前几名亲手开关、体验、拍板 | 用 Doom 的引擎包在一台手机上一键打开优化版和原版 | Codex-Sub（后端），Claude-Sub（网页） |
| Z6 | **中心节点一键切换成从节点**，接入更大的手机池 | 一台独立节点在网页上点一下就接入中心，它的手机出现在中心的手机列表里 | Codex-Sub |

## 顺序

- **第一波（现在）**：K1、Z2、Z1。分布式和"结构"页是领导场景 1 的第一屏；Z1 小，先做掉。
- **第二波**：K2、K3、Z3、Z4。
- **第三波**：K4、Z5、Z6。

每个 PR 合入前由 glm-filler 审；上线后由 glm-researcher 按普通用户的方式试用，记下别扭的地方。
