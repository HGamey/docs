# 自研超分+插帧 · 第 6 步：交付与推广（换游戏已做；换手机：荣耀上层能加载，性能未测准）

## 一键复现

```
sh loop_v1/selfsr/repro.sh <serial> [配对数=6] [输出目录] [包名=com.miHoYo.Yuanshen]
```

- 现编层 → 依次跑 6 组 A/B（透传层、满分辨率超分、降分辨率+超分、插帧、G-FRC+ 对标 ×2；没有 G-FRC+ 的机器跳过后两组）
  → 每组出 `report.md` / `report.json` / 每臂截图 → 汇总 `summary.md`。
- 满分辨率超分的目标分辨率取本机屏幕（`wm size`），换机不用改。
- 已知游戏的进门方式写在脚本里：原神走 `phonefarm onboard`；Megacity Metro 用固定进门脚本，并全程保留层属性
  （`--enter-script` / `--keep-layer-prop`，原因见下）。
- 每组结束（含 Ctrl-C）都会恢复并回读核对 Game Mode、G-FRC+ 位、`debug.knobs.*`、刷新率、风扇、屏幕超时，层会被摘除
  （`CHECKS_STEP0_2.md`）。
- 前提：手机已 root，游戏已装好；需要账号的游戏要先人工登录一次。

## 换游戏：Unity《Megacity Metro》（RedMagic NX809J，同一台机器）

选它是因为：已经装在机器上，不需要账号，Vulkan，并且和原神引擎不同版本、渲染管线不同（URP + 胶片颗粒）。
游戏把 2068×935 交给系统，HWC 放大到 2688×1216 上屏（和原神同一类问题）。

推广时遇到两个问题，都已解决：
1. `onboard` 认不出这款游戏「已经在游戏里」（画面里没有它认识的 HUD），所以加了 `--enter-script`：
   单人模式 → 关掉「链接 Unity 账号」提示 → 点任意处开始。不登录，不接受任何条款。
2. 层被加载了，但一帧都没拦到：Unity 先建一个探测用的 VkInstance，等真正建实例时，会话已经把 `debug.vulkan.layers` 清掉了。
   加了 `--keep-layer-prop`，会话期间一直保留这个属性。

### 结果（各 6 对，p 为精确符号翻转检验）

| 指标 | 原生 | 超分 锐化 0 | p | 超分 锐化 1.0 | p |
|---|---|---|---|---|---|
| 整帧锐度 | 49 | 71（**+46%**） | 0.031 | 411（+722%） | 0.031 |
| 右上角固定区锐度 | 9.9 | 20.4（**+107%**） | 0.031 | 65.9（+572%） | 0.031 |
| 与原生截图 SSIM | 0.90 | 0.86（−3.9%，**不显著**） | 0.38 | 0.78（−17%） | 0.031 |
| 上屏帧率 | 29.8 | 28.4（−4.7%） | 0.063 | 29.0（−2.8%） | 0.19 |
| 每帧 GPU 忙碌 (ms) | 24.4 | 27.1（+2.7） | 0.031 | 26.5（+2.6） | 0.063 |
| SF 丢帧 / 窗口 | 2.3 | **0** | 0.031 | 0 | 0.063 |

截图对比：`step6/megacity_crops.png`（原生 / 锐化 0 / 锐化 1.0）。

- **锐化 0 达到第 3 步的画质标准**：锐度显著提高，SSIM 下降不显著。
- **锐化 1.0 不能用在这款游戏上**：它把胶片颗粒放大成了噪点（天空明显）。拉普拉斯锐度会把噪点也算成「锐」，
  所以 +722% 是假象，SSIM 显著下降。原神没有颗粒，锐化 1.0 是合适的。
  **结论：锐化强度必须按游戏选，默认值应当偏保守。** `repro.sh` 对 Megacity 用 `SR_FULL=<屏幕>:0` 跑。
- 代价：每帧 GPU 多 2.7 ms，上屏帧率约 −4.7%（p = 0.063，接近显著）。这台机器热了以后被厂商卡在 30 帧，GPU 余量也小。

## 追加 (2026-10-26)：换手机——荣耀 AAP-AN00，不 root

荣耀现在能用，但没有 root，原神也不是可调试版，所以没法给原神挂层。改用可调试的测试程序 refbench（`frag_alu`，强度 16 时约 60 帧），
走 Android 自带的 GPU 调试层机制（`enable_gpu_debug_layers` / `gpu_debug_app` / `gpu_debug_layers`，层放进 app 私有目录），全程不用 root。
脚本：`step6/honor_noroot/noroot_smoke.sh <serial> [层.so] [轮数]`；结束后三项设置删回系统默认，debug.knobs.* 清空。

结果（3 轮，`step6/honor_noroot/summary.txt`）：
- **能推广的部分**：同一个层二进制在荣耀上不用 root 就能加载（logcat `Loaded layer VK_LAYER_refknobs_readonly`，marker `layer_loaded=true`），
  透传、超分、子图层插帧三种模式都能跑起来，插帧子图层 `selfsr_interp` 正常出现在 SurfaceFlinger 里。
- **性能结论不成立**：手机持续发热（机身 43 °C，thermal 状态 3），原生一臂从 59.9 掉到 44.9、32.2 帧，各臂顺序跑，没法比。
  第 1 轮透传 45.1 vs 原生 59.9，掉得比红魔上多，原因没查。插帧一臂子图层只有 26–36 帧，**在荣耀上没有翻倍**。
- 要得到可信的荣耀性能数，需要风扇/降温和 A/B 交替（红魔那套 `--fan --cool-max`），并且最好用可调试或可 root 的游戏。

### 追加：荣耀上插帧 60 → 120 翻倍（2026-10-26，不 root）

上面那次的插帧之所以没翻倍，是因为测试负载自己就把 GPU 吃满了才跑到 60 帧（强度 16），插帧再占一份 GPU，
游戏就掉到 37–41 帧，上屏只有 43–47 帧（等温到 35 °C 后 2 轮，`step6/honor_cap60/uncapped_gpu_bound_summary.txt`）。
真实游戏是被限帧器或垂直同步钉在 60 帧，GPU 留有余量，所以给 refbench 加了 `fps_cap`（present 后按绝对时刻睡到下一帧），
用轻负载（强度 4，不限帧能跑 120）钉在 60 帧来模拟。

第一次跑翻倍了，但插帧画面错位（`step6/honor_cap60/before_fix_native_vs_interp.png`）：
refbench 按 `preTransform = ROTATE_90` 预旋转画面，驱动给父图层设了反向的缓冲变换，子图层不继承它。
层改成按 swapchain 的 preTransform 自动给子图层设反向变换（ROTATE_90 → ANATIVEWINDOW_TRANSFORM_ROTATE_270，宽高对调），
marker 里 `interp.sc.xform` 记实际用的值。原神交的画面不预旋转（红魔上旧代码画面就是对的），走 transform 0，行为不变。

修好后 4 对（原生 / 插帧交替，每臂开跑前等机身 < 36 °C；`step6/honor_cap60/summary.txt`）：

| 指标 | 原生 | 插帧（子图层） |
|---|---|---|
| 实际上屏帧率 | 60.0 | **119.9**（119.4–120.4，×2.0） |
| 程序自己的帧率 | 60.0 | 60.0 |
| 真实帧 / 插帧 | — | 1499 / 1498（每个真实帧后插一帧） |
| 给真实帧加的延迟（p50） | — | +33.4 ms |
| 画面 | — | 和原生一致（`after_fix_native_vs_interp.png`） |

4 对时符号翻转检验的最小 p 是 0.125，但 4 对全部在 119.4–120.4，原生全部在 59.9–60.2，没有重叠。
结论：**同一个层，在第二台手机上不用 root 就能插帧到 120**。红魔上只有 89 帧，卡在厂商给游戏进程的 vsync 节拍（STEP4），不是方法本身的问题。
局限：荣耀上测的是可调试的测试程序，不是原神（原神不可调试，没 root 挂不上层）。

### 追加：荣耀上换游戏——Megacity Metro 插帧 30 → 60（2026-10-26，不 root）

荣耀不 root，游戏必须可调试才能挂层。Megacity Metro 是 Unity 的开源示例，所以用 apktool 加 `android:debuggable="true"` 重新打包、签名后装到荣耀上
（`~/hgamey-work/megacity_dbg/megacity_debuggable.apk`）。原神不能这样做（商业游戏，重打包违反其条款且有完整性校验）。
进游戏的步骤和红魔相同（单人模式 → 关提示 → 点任意处）。游戏启动时会请求麦克风权限，一律点「禁止」，没有授予任何权限。
脚本：`step6/honor_megacity/megacity_noroot.sh <serial> <层.so> [轮数]`，每臂开跑前等机身温度 < 36 °C，结束后三项 GPU 调试设置删回默认。

结果（3 对，原生 / 插帧交替；`step6/honor_megacity/summary.txt`）：

| 指标 | 原生 | 插帧（子图层） |
|---|---|---|
| 游戏自身帧率 | 30.1 | 30.1（30.0–30.1，不变） |
| 实际上屏帧率 | 30.1 | **60.1**（59.9–60.2，×2.0） |
| 给真实帧加的延迟（p50） | — | +69.6 ms |
| 画面 | — | 正常（`native_vs_interp.png`，两张里的飞船不同是游戏随机选的） |

- 同一个层二进制、同一套参数（只把投票帧率设为 60、`lead_ns` 50 ms），第二台手机、第二款游戏都翻倍。
- 延迟比 60 帧源时大：源帧间隔 33 ms，插帧要等下一帧到了才能算中间帧，再加 50 ms 提前量。
- 3 对时符号翻转检验最小 p = 0.25，但 3 对全部在 59.9–60.2，原生全部 30.1，没有重叠。
