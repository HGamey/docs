① 超分

超分：问题出在哪、我们怎么放大、怎么锐化

问题：画面是被屏幕硬件「糊」大的

原神在这台手机上并不按屏幕分辨率渲染。它画 2141×969，交给系统后，由显示硬件（HWC）用双线性插值放大 1.256 倍到屏幕的 2688×1216。双线性每个像素只看周围 2×2 个点，放大后边缘和细纹理都会变软。离线测量里，双线性放大后的锐度只有真值的 0.45 倍。

做法：在交给系统之前，自己放大到屏幕分辨率

  1. 改交换链尺寸：游戏创建交换链（用来送显的那组图）时，层把尺寸从 2141×969 改成屏幕的 2688×1216。游戏自己的渲染目标仍是 2141×969，所以它只画在每张图的左上角，不需要改游戏的任何逻辑。
  2. 送显前放大并锐化：游戏调 vkQueuePresentKHR 时，层先跑一次 compute shader，把左上角 2141×969 放大成整张 2688×1216，直接写回这张交换链图（省一次整图拷贝），然后再交给系统。
  3. 系统不再二次放大：交给系统的已经是屏幕原生尺寸，HWC 只需 1:1 显示。

放大：Catmull-Rom 双三次插值

每个输出像素按距离加权周围 4×4 = 16 个源像素。权重来自三次曲线（离中心越近权重越大，外圈权重为负，用来保持边缘的反差）：

w0 = f·(−0.5 + f·(1 − 0.5f))
w1 = 1 + f²·(−2.5 + 1.5f)
w2 = f·(0.5 + f·(2 − 1.5f))
w3 = f²·(−0.5 + 0.5f)      f = 小数位置

优化：中间两列（行）的权重同号，可以合并成一次硬件双线性采样，所以 16 次读取变成 9 次硬件采样，也不用算三角函数。

锐化：RCAS（对比度自适应）

取 AMD FSR1 的 RCAS 思路。对每个像素看上下左右 4 个邻居：

mn, mx = 邻域最暗、最亮值
lobe = 能让结果不超出 [0, 1] 的
       最大负权重，上限 0.1875
lobe = lobe × 强度
输出 = (lobe·(上+下+左+右) + 中心)
       / (4·lobe + 1)

效果：锐化力度随局部对比度自动调节，负权重有上限（0.1875），结果不会被推出 0–1 的亮度范围。高对比边缘仍会有一点过冲（例如 0.25/0.75 的台阶变成 0.198/0.802），属于轻微、受控的光晕；所以锐化强度要按游戏调。

工程优化：一次 GPU 调度完成

放大和锐化写在同一个 compute shader 里。每个工作组负责 16×16 个输出像素，先把这块外加一圈（18×18）的放大结果算进片上共享内存，再在共享内存里做锐化并写出。中间结果不落地，省掉一整张 2688×1216 图的写出和读回。实测超分每帧 GPU 耗时 1.06 ms（p95 1.09 ms）。

② 插帧算法

块匹配运动补偿，4 个 GPU 计算步骤

中间帧 = 把前一帧和当前帧各自沿运动方向挪到「半步」的位置，再取平均。难点在于估准每块画面往哪里动。

  1. 算亮度小图：把两帧缩到 1/4 分辨率的整数亮度图（每格 = 4×4 像素的加权亮度和）。全程用整数，GPU 结果和离线参考实现逐位一致，方便验证。
  2. 块匹配：小图上每 8×8 一块（对应原图 32×32 像素），在后一帧的 ±64 像素范围内逐个尝试 33×33 = 1089 个位置，找差异（SAD）最小的那个作为这块的运动方向。差异相同时选位移更小的，避免平坦区域乱跳。
  3. 平滑运动场：先做 3×3 中值滤波去掉个别错配的块，再做 5×5 平滑，让相邻块的运动连续，减少画面撕裂。
  4. 合成中间帧：每个像素按运动场，从前一帧往前挪半步取色、从后一帧往回挪半步取色，两者取平均。

已知局限：镜头转动时，插出来的中间帧里界面文字、小地图标签会有明显重影（见下面的慢放视频）：界面不跟场景一起运动，块匹配却按场景的运动去挪它。代码里有「界面区域直接取最近真实帧」的保护，但默认关闭、还没调好，这是下一步要做的。物体边缘也有块匹配常见的拖影。静止和慢速画面干净。

③ 送显路径

帧率从 30 到 118，过了三道关

算法写好后，帧率并没有自动翻倍。真正花时间的是让每一张画面都能按时上屏。

30 → 60解开游戏进程里的限帧器

系统在游戏进程加载的图形库里放了一个限帧器，按温度下发目标帧率，把每秒送显次数卡在 30。层启动时在进程内存里找到这个图形库，解析它的符号表定位到限帧配置，并把它关掉。

60 → 89中间帧改走自己的子图层

中间帧如果和真实帧一起走游戏的送显队列，也会被计入限帧次数，结果只是把一半真实帧换成了中间帧。我们改为在游戏窗口上挂一个自己的图层（Android 的 ASurfaceControl），把真实帧拷一份、中间帧画在自己的缓冲里，直接交给系统合成器。每张都带「期望上屏时刻」：第一张定在 25 ms 之后，留给 GPU 算完；后面每张间隔至少一个刷新周期，避免两张挤进同一个 vsync 只显示后一张。

89 → 118关掉合成器的「等游戏帧」机制

系统合成器在合成时，如果游戏这一帧还没画完，会每 1 ms 查一次，最多等 7–8 ms。这一帧因此合成晚了，下一个刷新周期被整帧跳过，排在那一格的中间帧和下一张撞车被丢掉，约 1/4 的帧因此丢失。这是从合成器的性能跟踪里一帧一帧对出来的。它有一个运行时开关，关掉后上屏到 118。

排查中试过但无效的做法：给游戏改帧率投票、定时叫醒合成器、把上屏时刻对齐 vsync 网格、真实帧交出前在 CPU 上等 GPU（这一项让游戏掉到 22 帧）。

延迟 +33.5 ms 是怎么来的

真实帧不再是一画完就上屏，而是排在中间帧后面：先留 25 ms 给 GPU 算中间帧，中间帧占一个刷新周期（8.3 ms），真实帧再上屏。25 + 8.3 ≈ 33.5 ms。把这 25 ms 缩到 12 ms 可以让延迟降到约 21 ms，但会有更多帧来不及上屏。这是下一步可以优化的方向。

实现规格

模型多大、算多少、占多少

每次 vkQueuePresentKHR 时发生的事（按顺序）

  1. 游戏把画好的一帧交过来。层在游戏创建交换链时已把它改成屏幕原生 2688×1216，游戏仍按 2141×969 画在左上角。
  2. 超分：一次 compute 调度，把左上角 2141×969 放大并锐化成整张 2688×1216。
  3. 插帧：用上一帧和这一帧跑亮度小图、块匹配、平滑、合成四步，把中间帧写进环形队列里的一张送显缓冲。
  4. 把这一帧原样拷进下一张送显缓冲，再拷一份留作「上一帧」。
  5. 给两张缓冲加屏障，把所有权交给系统；整批命令提交到 GPU，导出一个同步 fd，CPU 不等 GPU。
  6. 用一个 ASurfaceTransaction 把两张缓冲交给子图层：中间帧期望上屏时刻 = 现在 + 25 ms，真实帧再晚半个游戏周期，相邻至少隔一个刷新周期减 0.3 ms。
  7. 游戏自己的送显照常进行。它被不透明的子图层盖在下面，看不见，但游戏的节奏不受影响。
  8. 子图层第一次出现时设置一次：盖在游戏图层上方、声明不透明、按游戏的预旋转方向设变换、投 120 Hz 帧率票。

上线前要知道的

插帧要关掉手机系统合成器里的一个「等游戏帧」机制，帧率才能到 118。它会在游戏画面没画完时等待最多 7–8 ms，导致下一帧被整帧跳过，插帧因此卡在 89 帧。关闭它是一条运行时命令，不改系统文件，测试结束自动恢复，但需要 root。正式上线需要手机厂商配合，请求已经写好。

  • 延迟 +33.5 ms 是层内记录的排队时间，是下限，还没有用外部高速相机测端到端的操作延迟。
  • 重影：镜头转动时，插出来的中间帧里界面会被块匹配按场景运动拖出重影（界面不跟场景动）。已加「静止保护」：两帧之间几乎不变的像素不做运动补偿，运动采样落到这种像素上就丢掉、改用另一侧，不用手工标界面框。正式 4 对 A/B：转视角时界面区相邻帧差 −35%（4/4 对，p=0.125），帧率、GPU 不变，现已默认开启（阈值 32）。文字（UID 等）重影基本消失；半透明的技能图标边缘仍有轻微拖影（底下场景在动，判不成静止）。物体边缘的块匹配拖影不在这次处理范围内。
  • 每款游戏只测了一个静置场景。
  • 原神只在主测手机上测过，第二台手机上没有跑原神。

3. 层是怎么挂进游戏的

root 设备（gray-layer session）

  1. 会话先拿设备租约。
  2. 把 .so 拷进游戏的 native 库目录（/data/app/…/lib/arm64）。
  3. 设 debug.vulkan.layers=VK_LAYER_refknobs，然后冷启动游戏。
  4. 游戏建 VkInstance 时，Android 的 Vulkan loader 会加载这个层。
  5. 会话结束时删 .so、清属性。

每臂结束后，selfsr_ab.py 会再独立核对一次：.so 不在、属性为空。核对不通过，整轮立刻中止。

非 root 设备（noroot_smoke.sh）

  1. 目标 App 必须是可调试的。我们用自编的 refbench，以及重打包成可调试的第三方游戏。
  2. 设 settings global enable_gpu_debug_layers=1、gpu_debug_app=<包名>、gpu_debug_layers=VK_LAYER_refknobs。
  3. 用 run-as <包名> cp 把 .so 放进 App 私有目录。
  4. 结束时删回这三项 settings，并删掉 .so。

5. 一臂的完整步骤

  1. 降温：--cool-max 40 时，先停游戏、熄屏，直到电池温度 ≤ 40 °C（最多等 15 分钟）。过热时系统会压帧率、弹高温窗口。整轮用 --fan 把机身风扇开到最高，收尾写回原值。
  2. 加锁并设置：不挂层的臂整臂在 tools/devlock 下跑。挂层的臂由 gray-layer session 持有设备租约。设置内容包括 Game Mode 干预、debug.knobs.* 和厂商功能开关。
  3. 冷启动并进世界：phonefarm onboard --enter-only 用截图和 OCR 识别界面，点「点击进入」等按钮进到大世界。它认不出的游戏，用 --enter-script 's:<秒>;t:<x>,<y>;…' 固定点击序列。不登录、不改游戏内任何设置。
  4. 进世界之后再设：刷新率、sfwait、sfovr。原因是有的系统在游戏启动时会把刷新率压回 60 Hz，启动前设会被覆盖。
  5. 静置：--settle 秒（默认 20）。
  6. 测量窗口：--window 秒（正式结果用 60），5 路数据并行采集，见第 6 节。
  7. 收尾：停会话、摘层、am force-stop，核对层已不在。

8. 插帧要越过的三道系统关卡

插帧的目标是在 60 帧的游戏上做到上屏约 120 帧。在实际设备上，算法本身之外还有三道关卡。

  1. 进程内限帧器：部分系统定制的 libgui 在应用进程内限制每秒送显次数。层多送的合成帧也算在里面，结果只是把一半真实帧换成了合成帧，总数不变。
    • 层的 unlimit=1 在进程内找到这个限帧器的配置，把它解开。
    • 插帧本身改走 子图层：在游戏窗口下挂一个 ASurfaceControl 子图层，真实帧拷一份、合成帧画进层自己的 AHardwareBuffer，用 ASurfaceTransaction 直接交给 SurfaceFlinger，不经过被限帧的缓冲队列。
  2. 按 vsync 排上屏时刻：
    • 同一游戏帧的合成帧和真实帧如果在同一个 vsync 就绪，SF 只显示后一张。所以第一张定在「现在 + 提前量」，后面每张间隔至少一个刷新周期，每张都带 desiredPresentTime。
    • 子图层还要做旋转：游戏按 preTransform 预旋转时，子图层设相同的反向变换。
  3. 定制 SF 的「等游戏帧」特性：
    • 现象：有的定制 SurfaceFlinger 在合成时，如果游戏图层的缓冲 GPU 还没画完，会每 1 ms 轮询一次，最多等 7–8 ms。这一帧因此合成晚了，下一个 vsync 因为 backpressure 整帧跳过。那一格排好的子图层缓冲，下次和后一张一起就绪，前一张被顶掉。最终上屏卡在约 89 帧。
    • 定位方法：在测量窗口内另开 atrace -t 3 gfx view，看 SF 主线程的 commit → fence unsignaled → 一串 wait → 下一次 PrevFramePending / onCommitNotComposited，以及子图层的 releasePendingBuffer。
    • 处理：该 SF 自带运行时开关 dumpsys SurfaceFlinger --fpsControl_waitframe_off，不改系统文件。sfwait=off 在进世界后关掉它，收尾写回开。关掉后子图层上屏约 118–120 帧。
    • 排查中试过、但无效的做法（STEP4 有完整表格）：
      • 用 SF 后门（service call SurfaceFlinger 1039）把 uid 帧率覆盖改成 120；
      • 定时给 SF 发空事务叫醒它；
      • 把上屏时刻对齐 vsync 网格；
      • 真实帧交出前在 CPU 上等 GPU 做完（游戏渲染掉到 22 帧）。

10. 踩过的坑

  • 收尾可能在另一个进程：每臂的设置和收尾经 tools/devlock run 在子进程里执行，主进程里记的状态传不过去。凡是「进世界后才设」的东西，收尾都按设备上的实际状态清理，不依赖进程内变量：
    • sfovr：读 SF 里现有的后门条目，逐条删除；
    • sfwait：在有这个开关的系统上一律写回开。
  • 不要并行跑两轮同一台设备：后一轮开跑时会把前一轮改过、还没还原的值记成「原值」。前一轮完全退出后再开下一轮。
  • 不要删还在恢复中的输出目录：挂层会话失败时，租约会留下「需恢复」屏障，恢复要读会话目录里的记录。删了目录就只能手工清租约（备份租约目录，并在 phonefarm-recovery.jsonl 里记一条原因）。
  • 锁队列是全局的：一台设备的残留请求会挡住所有设备。被杀掉的进程留下的队首请求，10 分钟后才会被跳过。
  • HWC 层表的列数因系统而异：有的系统多一列 [*]。Source Crop 要按「4 个带小数点的数」识别，不能按固定列号取。
  • 热：同一设备连续跑，电池温度会逼近系统的降帧阈值，屏幕会被压回 60 Hz（这一臂会因 panel 回读失败而作废）。降温阈值设低一点（40 °C），配合风扇。
  • 算延迟用的时钟：层用 CLOCK_MONOTONIC，/proc/uptime 包含休眠时间，两者对不齐。窗口统计以层 CSV 里最后一条上屏时刻为终点往前取。

为什么帧率上不去：30 帧是厂商策略，不是 GPU 算力

  • 被污染的那次（ab6_gfrc101_vs_srfull_SUSPECT）里，GFRC+ 没关干净，自研超分臂也跑到了 59.3 帧， 每帧 GPU 时间 16.2 ms，只比 GFRC+ 多 1.4 ms（我们的层自身约 2.2 ms，第 3 步测过）。 只要 GFRC+ 开着，系统就放开到 60 帧；GFRC+ 一关，不管挂不挂我们的层，都回到 30 帧。
  • 第 4 步定位到的限帧器（libgui.so 的 FpsControl/IFAS）在游戏进程内按系统下发的目标帧率卡送显次数。 GFRC+ 是厂商自己的功能，会同时把这个目标抬高。
  • 所以在主测手机上，第三方超分/插帧拿到的帧率预算只有厂商功能的一半。这是平台限制，要在报告里写给厂商。 我们不绕过这个系统限制。

代码级说明

代码里是怎么实现的

代码在 HGamey/phonefarm 仓库的 feat/selfsr 分支。层的源码在 knobs/gray/layer/，测试脚本在 loop_v1/selfsr/。下面的代码片段都摘自源码，只删了日志和部分注释，删掉的地方用 // … 标出。

1. 层怎么被加载、怎么拦截调用

层是一个 libVkLayer_refknobs.so，层名 VK_LAYER_refknobs_readonly。Android 的 Vulkan 加载器不读 JSON 清单（VkLayer_refknobs.json 只给桌面加载器用）。它在应用自己的 native 库目录里找 .so，用 dlsym 取 4 个枚举函数和 vkNegotiateLoaderLayerInterfaceVersion，缺一个就丢掉这个层。

上机用的是 root 路线：把 .so 拷进游戏的 nativeLibraryDir（/data/app/…/lib/arm64），再 setprop debug.vulkan.layers VK_LAYER_refknobs_readonly。这个属性是全局的，会影响别的 Vulkan 应用，所以测试会话在游戏加载完层之后立刻把它清空（src/gray_session.rs）。不 root 的标准做法是 settings put global enable_gpu_debug_layers / gpu_debug_app / gpu_debug_layers，但系统只对可调试应用生效：对原神这类不可调试的商业游戏无效；在第二台手机上，用可调试的测试程序和重打包成可调试版的 Megacity，不 root 也成功加载了层（插帧 60→119.9、30→60.1）。

加载器通过协商拿到我们的 GetInstanceProcAddr / GetDeviceProcAddr。游戏每查一个函数，先问超分、插帧、抓帧三个模块要不要接（没开的模块恒返回空），再查本层的钩子表，都不要就原样转给下一层。正式测试实际接管的入口：

  • 实例级：vkCreateInstance、vkDestroyInstance、vkCreateDevice（加 VK_GOOGLE_display_timing 和 AHardwareBuffer 导入扩展）、vkEnumerateDeviceExtensionProperties（只转发）、vkCreateAndroidSurfaceKHR（插帧开时才接，用来拿游戏窗口）。
  • 设备级：vkQueuePresentKHR、vkCreateSwapchainKHR、vkDestroySwapchainKHR、vkDestroyDevice、vkGetDeviceQueue / vkGetDeviceQueue2（记队列族）、vkGetPastPresentationTimingGOOGLE。
  • 另有 render pass、draw、提交等观测用钩子，只在 passdump / frameaudit 等属性打开时才挂，正式测试不挂。

2. 改交换链

游戏建交换链时，超分模块把 imageExtent 换成屏幕分辨率，并加上拷贝用的用途位。游戏的帧缓冲还是原来的小尺寸（帧缓冲允许比图像小），所以它只画在每张图的左上角。插帧模块在同一个调用里多要几张图（缺省多 2 张），加用途位，并强制 FIFO。改过的参数建不成，就退回游戏的原参数，画面照常，只是不超分不插帧。

交换链建好后，超分模块再建三张自己的图：T（游戏尺寸，采样读）、O 和 P（屏幕尺寸，计算着色器写），以及每张交换链图一个信号量。子图层路线的插帧帧不放在交换链里，而是放在另外一组共享缓冲里，见第 6 节。

3. vkQueuePresentKHR 主流程

游戏每送显一次，层先解开限帧（第 8 节），然后串起两个模块：超分模块录一批命令，等游戏的信号量，做完发出自己的信号量；它不直接送显，而是把「改成等这个信号量」的送显请求交给插帧模块。插帧模块再录一批命令（插帧、拷真实帧、存历史帧），等超分的信号量，提交后导出一个同步 fd，把两张缓冲交给子图层，最后把游戏原来的送显转下去，让它等插帧的信号量。

CPU 全程不等 GPU：子图层靠同步 fd 自己等。任何一步失败都走 bail()，按游戏的原参数送显，并把原因计数写进日志文件。

4. 超分调度

超分一共一次计算调度。先把游戏画的左上角拷进 T，再绑定描述符集：binding 0 是 T（带采样器，Catmull-Rom 要用硬件双线性），binding 1 是输出图 O（storage image）。推送常量 32 字节：输入尺寸、输出尺寸、锐化强度、算法编号。工作组 16×16，按输出尺寸向上取整。

着色器里每个工作组先把 18×18 的放大结果（多一圈邻居）算进共享内存，Catmull-Rom 用 9 次双线性取样代替 16 次取点。然后直接在共享内存上做 RCAS 锐化写出，省掉一整张中间图的写出和读回。交换链图支持存储写入时直接写进交换链图（正式测试走的就是这条，9128 帧全部直写）；不支持时先写到层自己的图 O，再拷回交换链图。

5. 块匹配着色器

块匹配在 1/4 分辨率的亮度图上做。一个工作组 256 个线程负责一个 8×8 块：先把这块和后一帧里周围 ±16 的窗口（40×40）读进共享内存，再让 256 个线程分摊 33×33 = 1089 个候选位移，每个候选算 64 个像素的绝对差之和（SAD）。

比较用三元组（SAD，|dx|+|dy|，扫描序号）：SAD 相同就取位移小的，再相同取扫描序靠前的。这样平坦区域不会总落到搜索窗的角上。最后用共享内存做 8 轮归约，选出全组最小者，写出这块的 (dx, dy)。在 interp_bm.cpp: synth_bm 里它是 4 步中的第 2 步：亮度 → 块匹配 → 平滑 → 合成。

6. 子图层

插帧开着时，层接管 vkCreateAndroidSurfaceKHR，记下游戏的 ANativeWindow。第一次送显时用 ASurfaceControl_createFromWindow 在这个窗口下建一个子图层（名字 selfsr_interp）。相关函数都从 libandroid.so 里 dlsym 取，不加链接依赖。

送显缓冲是层自己分配的 AHardwareBuffer（环形 8 张），通过 VK_ANDROID_external_memory_android_hardware_buffer 导入成 VkImage，GPU 直接往里写。每张缓冲一个 ASurfaceTransaction：setBuffer（带同步 fd）、setDesiredPresentTime、apply。第一次还要设几何和变换（跟随游戏的预旋转）、z 序 1（盖在游戏图层上面）、120 Hz 帧率票，并声明不透明。不声明不透明的话，合成器会把下面的游戏图层混进来，HUD 出现双影。

7. 上屏时刻排程

每个游戏帧送两张：先中间帧，后真实帧。第一张的期望时刻 t0 = 现在 + 提前量（正式测试 25 ms），真实帧再晚 step，即半个游戏周期（游戏送显间隔的滑动平均除以 2）。

slot() 保证相邻两张至少隔 gap = 一个刷新周期减 0.3 ms（120 Hz 时约 8.03 ms）。太近的话两张会落进同一个刷新周期，合成器只显示后一张。如果之前排的已经积压超过一个游戏周期，这一帧就不插中间帧，只送真实帧，避免延迟越滚越大。

8. 解开进程内限帧

系统图形库里有一份进程内的限帧配置，游戏每次送显时会按它补睡眠，把帧率压到系统给的目标（发热时是 30）。层在 vkCreateInstance 时找到读这份配置的函数 getGlobalConfig：先试 dlopen；不 root 加载时应用的链接器命名空间看不到系统内部库，就用 dl_iterate_phdr 找到这个库在进程里的装载基址，再从磁盘读它 ELF 的 .dynsym，查到符号偏移，加上基址就是函数地址。

之后每次送显前调一次这个函数拿到配置指针，把偏移 0x60 处的限帧值清零，并计数。这个偏移只对实测的系统版本成立；找不到符号或指针为空时什么都不做，原因写进日志文件。

9. 一键开关与还原

层的所有行为都由 debug.knobs.* 系统属性控制，在 vkCreateInstance 时读一次。属性为空就是关：模块不接任何调用、不改交换链，层只做透传。开关都不改游戏的文件和设置，也不需要重新打包游戏。

测试脚本收尾（包括 Ctrl-C）走 restore：结束游戏，还原 Game Mode，清空所有 debug.knobs.*，写回厂商超分插帧设置的原值。restore_panel 删掉合成器后门里给游戏 uid 下的帧率覆盖，把合成器的「等游戏帧」写回开，屏幕刷新率和帧节奏属性按开跑前记下的原值写回。最后核对游戏 lib 目录里没有 .so、debug.vulkan.layers 为空，结果写进 restore.json。

10. 测试脚本入口

repro.sh 一条命令跑完全部对照组，每组调 selfsr_ab.py run --a <臂> --b <臂>，冷启动 ABBA 交替。臂的写法：native（不挂层）、layer（只挂透传层）、sr:<降分辨率比例>:<宽>x<高>:<锐化>、ip:<合成方式>:<帧率>:键=值,…、srip:…（超分 + 插帧）。

measure() 在同一个时间窗口里并行采：合成器 timestats（游戏图层的上屏帧率、丢帧）、dumpsys SurfaceFlinger --latency selfsr_interp#N（子图层的实际上屏时刻，timestats 不收子图层）、ftrace 解析出的游戏 GPU 提交（游戏渲染帧率、p95 帧时、GPU 忙碌时间），以及一张截图（锐度）。
